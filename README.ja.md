# claude-code-misread-lexicon

[![test](https://github.com/kai-chop/claude-code-misread-lexicon/actions/workflows/test.yml/badge.svg)](https://github.com/kai-chop/claude-code-misread-lexicon/actions/workflows/test.yml)

**エージェントは指示を無視したのではなく、語をひとつ違う意味で読んだ。** 誤読される語の型を登録する台帳と、
それを書き直させるlinter、そして**過去ログに埋まっている誤読を遡って掘り起こす採掘器**。

> 🇬🇧 **English**: [README.md](README.md)

## これは何の問題を解くのか

エージェントが違うことをした時、つい「ルールを足す」で解こうとします。しかしこの種の失敗のかなりの割合は、
不服従でもルール不足でもありません。**指示は在って、その中の語ひとつが別のものに解決された**だけです。

この失敗には厄介な性質があります。**書き手と読み手の両方から見えない**。書き手には意図どおりの文が見え、
読み手には筋の通った文が見える。例外も落ちるテストも出ず、ただ作業が別の方向へ行く。何も壊れて見えないので、
同じ語が何度でも同じことをします。

もうひとつの性質。**誤読は形で再発する**。日常語と衝突する2文字の略語は、どのモデルでも、どのセッションでも、
毎回「誤字」と読み替えられます。だから登録する価値がある——名前を付けられるクラスは、機械で見張れるクラスです。

## 何を実測したか

出発点は実在のエージェント・トランスクリプト群の走査です。**107本・人間の発話1220件**を、手書きの障害台帳と
突合しました。見つかった誤読は全て6つの型のどれかに収まりました。

| 型 | 機序 | 検出器 |
|---|---|---|
| **M1** 短い多義トークン | 2〜3文字の略語が日常語と衝突し、読み手が黙って「誤字」と再解釈する | ✅ 本linter |
| **M2** 非ASCII識別子の化け | 語がバイトとしては届くが経路（パイプ・符号化境界）で壊れ、**壊れた写しの方**を実体として診断してしまう | ⛔ 符号化ガードの担当。ここでは持たない |
| **M3** 語彙乖離 | docは書き手の語彙で書かれ、読み手は自分の語彙で検索し、空振りして「その機能は無い」と結論する | ⛔ 原理的に不能（後述） |
| **M4** 記号の構文衝突 | テキストとしては正しいが、描画すると別の意味になる（テーブルのセル内の生パイプ） | ⛔ markdown linterの担当 |
| **M5** 相対参照 | `昨日`・`上`・`前のセッション`——会話では成立し、後から読まれるdocでは参照先を失う | ✅ 本linter |
| **M6** 片側列挙の判定語 | 判定語が「含まれるもの」だけを列挙して否定側を閉じないため、読み手が**対象外を発明する** | ⛔ 手監査（後述） |

**6つのうち検出器が付くのは2つ。これは不足ではなく設計です。**

- **M2とM4には既に所管がある**。既存ガードが見ている領域へ3つ目の検査器を足すと、食い違う2つができて
  どちらも信用されなくなります。ここは既存ツールへ向けてください。
- **M3は構造的に検出できない**。検出するとは「誰も書かなかった同義語の**不在**」を検出することです。
  無い語をlinterは見つけられません。台帳には「手で見分ける型」として残します——実測コーパスでは**最多**の
  クラスでした。だからこそ自動化を騙るのが一番害のある選択になります。
- **M6は意図的に手監査へ置いた**。実出現は約12件。12件の母集団に対する検出器は、使う時間より調整する時間の
  方が長くなります。

「じゃあ検出器を4つ足せばいい」と感じたなら、**その反射こそがこのリポジトリの反対しているもの**です。正常な
状態に鳴る検査器は無視される訓練を与え、その時点で何も守らなくなります。

## M6だけは節を分ける

6つの中でM6が最も馴染みが薄く、そして実測コーパスで**再発回数が最多**でした（同じ誤読が3回）。

「**非自明なタスク**（新サブシステム・委譲・大きな編集）ではXせよ」——完全な指示に見えます。違います。
何が非自明かは言っていますが、**何が非自明でないかを言っていない**。だから解析タスクを前にした読み手はこう
推論します: *例が全部コード作業だ、これは解析だ、よって対象外*。実測ケースでは、その読み手自身がやっていた
行為（**委譲**）が列挙の中に**在りました**。

教訓はここです。**例を増やしても直りません。** 該当する例は既に在って、読み飛ばされたのですから。直るのは
否定側を閉じた時だけです:

> ❌ `非自明なタスク（新サブシステム・委譲・大きな編集）では`
> ✅ `非自明なタスク——自明とは「1ファイル・10行未満・新規挙動なし・検索不要」が**全部**成立する場合のみ。**それ以外は全て該当**`

同じコーパスに後者の書き方をしたルールがあり、そちらには誤読の記録がありません。

## 導入

Python 3.8+。依存なし。

```bash
git clone https://github.com/kai-chop/claude-code-misread-lexicon
cd claude-code-misread-lexicon
cp misread-lexicon.example.json misread-lexicon.json   # 自分の置き場に合わせて編集
python tools/check_misread_words.py --self-test        # 自機で動くことを確認
```

設定（`misread-lexicon.json`）——パスは全て利用者が決めます。ハードコードはありません:

```json
{
  "roots": ["~/.claude", "~/.codex", "~/.gemini", "~/.config/github-copilot"],
  "lexicons": ["lexicon/lexicon.en.md", "lexicon/lexicon.ja.md"],
  "transcripts": "~/.claude/projects",
  "scan": [
    { "rules": ["M1"], "include": ["rules/**/*.md", "skills/**/*.md"], "exclude": ["ledgers/**"] },
    { "rules": ["M5"], "include": ["**/HANDOFF.md"], "exclude": ["ledgers/**"] }
  ]
}
```

2つのscanブロックで**スコープが違う**ことに注目してください。これは意図的で、ここが最重要の調整箇所です。
M1は指示文書に効かせます（誤読が作業の宛先を狂わせる場所だから）。M5は**自分の規約が既に絶対日付を要求して
いる場所**にだけ効かせます。全域に向けると、相対日付で何も問題ない散文に鳴り続けます——後述の「効くのは語でなく
スコープ」を参照。

### エージェントのdocはどこに住むか

1つの設定で複数のエージェントの拠点を同時に指せます——`roots`はリストを受け取ります。**存在しない拠点は
黙ってスキップされます**。全部インストールしている人はいないからです。aliveの行が
`roots=<存在>/<宣言>` を出すので、実際に何を走査したかが見えます:

```
[misread-lint] alive: rules=6 roots=2/4 targets=13
```

| 環境 | 拠点 | 指示docの置き場 |
|---|---|---|
| Claude Code | `~/.claude` | `CLAUDE.md`、`rules/`、`skills/`、`workflows/` |
| OpenAI Codex | `~/.codex` | `AGENTS.md`、`skills/` |
| Gemini CLI | `~/.gemini` | `GEMINI.md` |
| GitHub Copilot | リポジトリ内 | `.github/copilot-instructions.md` |
| Cursor | リポジトリ内 | `.cursor/rules/**`、`.cursorrules` |
| 共通 | リポジトリ内 | `AGENTS.md`、`HANDOFF.md` |

プロジェクト単位のdocはホームディレクトリでなく、作業しているリポジトリの中に住みます——そちらのパスも
`roots` へ足してください。例: `"roots": ["~/.claude", "."]`。

**正直に書く限界**: `mine_misreads.py` が検証済みなのはClaude CodeのJSONLトランスクリプト形式だけです——
`type: "user"`/`"assistant"` のレコードと、Anthropic形式の `message.content` ブロック。他ベンダーは会話
履歴を別の形で保存しており、この採掘器はそのどれに対しても検証されていません。誰かが確かめるまでは
Claude Code専用として扱ってください。このリポジトリはそれ以上の対応を謳いません。

## 使う

```bash
python tools/check_misread_words.py                    # 設定したスコープを走査
python tools/check_misread_words.py --paths FILE ...   # 特定ファイルだけ
python tools/mine_misreads.py --out candidates.jsonl   # 過去ログから誤読を掘り起こす
```

検出ありでexit 1、無しで0。**ファイルを書き換えることはありません**——位置と「伝わる形」を出すだけで、直すかは
利用者が決めます。

## 台帳は育つ、コードは育たない

linterは実行時に台帳のテーブルからルールを読みます。語の追加はテーブル1行です:

```
| M1 | UE | UE(Unreal Engine)（ファイル内初出時。以後は裸でよい） | 例 |
```

コード変更も再配布も要りません。**想定している運用は「実際に誤読が起きたその場で1行足す」**——この台帳は
他人が推測した辞書ではなく、**自分の事故の記録**です。だからほぼ空で出荷されます。

テーブルはヘッダ文字列ではなく**マーカーコメント**で位置特定するので、台帳は何語で書いても動きます。列は
位置で決まります（型・誤読される形・伝わる形・根拠）。

## 既に起きた誤読を回収する

前向きに育てるだけだと、ゼロから始めて痛い目に遭うのを待つことになります。`mine_misreads.py` は既存の
エージェント・トランスクリプトを読み、**既に起きた訂正**——人間が「そうじゃなくて」と言った瞬間——を、その直前に
エージェントが何を読んでいたかと一緒に出します。

候補は2段で報告されます: 読み違いを明示的に名指した発話と、一般的な訂正。パターンは英日両対応です。これは
**ゲートでなくレポート**なので常にexit 0を返します——どれが本物かは人が決める必要があるからです。

**歩留まりは低く、それでいい**。参照コーパスでは発話1220件から生の一致51件、そのうち大半は機械生成の会話
要約で、除外が必要でした。残ったのは僅かです——が、登録する価値があったのはその僅かの方でした。

## 効くのは語でなくスコープ

このツールの初回実走は検出3件と**誤検出1件**を出しました。そしてこのREADMEで一番役に立つのは誤検出の方です。

M5が個人的なノートの中の `明日` に発火しました。そこでの用法は概念的で——*「熱だけで再建
された明日」*——しかも一部は本人の発言の逐語引用でした。腐っているものは何もありません。**ルールは正しく、
スコープが間違っていた**。

処方は文を書き換えることではありません。**引用をlinterに直させてはいけない。** 処方はM5の既定スコープを
引き継ぎ文書に絞ることで、そして**その行そのものを負対照テストへ焼く**ことでした（スコープが黙って広がらない
ように）。

このリポジトリが求める規律はここです。検出器が誤爆した時の最初の問いは「検査器を満たすようにどう書き直すか」
ではなく、**「このファイルはそもそもスコープ内だったのか」**です。

### ⚠ このREADMEは意図的にcleanにならない

`--paths` は設定したスコープを無視して全ルールを当てます。だからこのリポジトリ自身のdocに向けると検出が出ます——
相対参照**について**書いた文書には、必然的に `昨日` や `明日` が出てくるからです。

その大半は**使用でなく言及**で、コードスパンで囲んであります（linterが免除する形）。これで9件が2件になりました。
残った2件は上の節の引用文で、各READMEに1件ずつです。これは検出されたまま、**書き換えずに残してあります**。
書き換えるとは、ツールが自分を満たすために人の言葉を直すということだからです。

どちらのファイルも既定の走査スコープには入っていないので、通常のスイープでは一度も見られません。教訓がそのまま
縮図になっています——**問題だったのはルールではなく、スコープの方**。

## これは何ではないか

- **スペルチェッカでも文体linterでもない**。散文の良し悪しに意見を持ちません。既に誤読された語の形だけを、
  しかも**登録された分だけ**知っています。
- **ガードではない**。何も遮断せず、何も書き換えません。報告して終わります。
- **符号化の修理屋ではない**。M2は網羅のために載せていますが、意図的に検出器を持ちません。
- **ファイルを読むことの代わりにはならない**。実測で最多だったM3は、まさにどんなツールでも捕まえられない型です。
  「その機能は無い」と言う前に、在るならそこに書かれているはずのファイルを開いてください。空振りした検索が
  証明するのは**自分の語彙が一致しなかったこと**だけで、対象の不在ではありません。
