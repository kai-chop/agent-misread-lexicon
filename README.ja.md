# agent-misread-lexicon

[![test](https://github.com/kai-chop/agent-misread-lexicon/actions/workflows/test.yml/badge.svg)](https://github.com/kai-chop/agent-misread-lexicon/actions/workflows/test.yml)

**エージェントは指示を無視したのではなく、語をひとつ違う意味で読んだ。** 誤読される語の型を登録する台帳と、
それを書き直させるlinter、そして**過去ログに埋まっている誤読を遡って掘り起こす採掘器**。

> 🇬🇧 **English**: [README.md](README.md)

## これは何の問題を解くのか

エージェントが違うことをした時、つい「ルールを足す」で解こうとします。しかしこの種の失敗のかなりの割合は、
不服従でもルール不足でもありません。**指示は在って、その中の語ひとつが別のものに解決された**だけです。

この失敗には厄介な性質があります。**書き手と読み手の両方から見えない**。書き手には意図どおりの文が見え、
読み手には筋の通った文が見える。例外も落ちるテストも出ず、ただ作業が別の方向へ行く。何も壊れて見えないので、
同じ語が何度でも同じことをします。

もうひとつの性質。**誤読は形で再発する**。日常語と衝突する2文字の略語は、どのモデルでも、どのセッションでも、
毎回「誤字」と読み替えられます。だから登録する価値がある——名前を付けられるクラスは、機械で見張れるクラスです。

## 何を実測したか

出発点は実在のエージェント・トランスクリプト群の走査です。**107本・人間の発話1220件**を、手書きの障害台帳と
突合しました。見つかった誤読は全て6つの型のどれかに収まりました。

![誤読がとる6つの型——2つは本linterが検出し、2つは既存ツールの所管、2つは意図的に検出器を持たない](assets/six-shapes-ja.svg)

| 型 | 機序 | 検出器 |
|---|---|---|
| **M1** 短い多義トークン | 2〜3文字の略語が日常語と衝突し、読み手が黙って「誤字」と再解釈する | ✅ 本linter |
| **M2** 非ASCII識別子の化け | 語がバイトとしては届くが経路（パイプ・符号化境界）で壊れ、**壊れた写しの方**を実体として診断してしまう | ⛔ 符号化ガードの担当。ここでは持たない |
| **M3** 語彙乖離 | docは書き手の語彙で書かれ、読み手は自分の語彙で検索し、空振りして「その機能は無い」と結論する | ⛔ 原理的に不能（後述） |
| **M4** 記号の構文衝突 | テキストとしては正しいが、描画すると別の意味になる（テーブルのセル内の生パイプ） | ⛔ markdown linterの担当 |
| **M5** 相対参照 | `昨日`・`上`・`前のセッション`——会話では成立し、後から読まれるdocでは参照先を失う | ✅ 本linter |
| **M6** 片側列挙の判定語 | 判定語が「含まれるもの」だけを列挙して否定側を閉じないため、読み手が**対象外を発明する** | ⛔ 手監査（後述） |

**6つのうち検出器が付くのは2つ。これは不足ではなく設計です。**

- **M2とM4には既に所管がある**。既存ガードが見ている領域へ3つ目の検査器を足すと、食い違う2つができて
  どちらも信用されなくなります。ここは既存ツールへ向けてください。
- **M3は構造的に検出できない**。検出するとは「誰も書かなかった同義語の**不在**」を検出することです。
  無い語をlinterは見つけられません。台帳には「手で見分ける型」として残します——実測コーパスでは**最多**の
  クラスでした。だからこそ自動化を騙るのが一番害のある選択になります。
- **M6は意図的に手監査へ置いた**。実出現は約12件。12件の母集団に対する検出器は、使う時間より調整する時間の
  方が長くなります。

「じゃあ検出器を4つ足せばいい」と感じたなら、**その反射こそがこのリポジトリの反対しているもの**です。正常な
状態に鳴る検査器は無視される訓練を与え、その時点で何も守らなくなります。

## M6だけは節を分ける

6つの中でM6が最も馴染みが薄く、そして実測コーパスで**再発回数が最多**でした（同じ誤読が3回）。

「**非自明なタスク**（新サブシステム・委譲・大きな編集）ではXせよ」——完全な指示に見えます。違います。
何が非自明かは言っていますが、**何が非自明でないかを言っていない**。だから解析タスクを前にした読み手はこう
推論します: *例が全部コード作業だ、これは解析だ、よって対象外*。実測ケースでは、その読み手自身がやっていた
行為（**委譲**）が列挙の中に**在りました**。

教訓はここです。**例を増やしても直りません。** 該当する例は既に在って、読み飛ばされたのですから。直るのは
否定側を閉じた時だけです:

> ❌ `非自明なタスク（新サブシステム・委譲・大きな編集）では`
> ✅ `非自明なタスク——自明とは「1ファイル・10行未満・新規挙動なし・検索不要」が**全部**成立する場合のみ。**それ以外は全て該当**`

同じコーパスに後者の書き方をしたルールがあり、そちらには誤読の記録がありません。

## 導入

Python 3.8+。依存なし。

```bash
git clone https://github.com/kai-chop/agent-misread-lexicon
cd agent-misread-lexicon
cp misread-lexicon.example.json misread-lexicon.json   # 自分の置き場に合わせて編集
python tools/check_misread_words.py --self-test        # 自機で動くことを確認
```

設定（`misread-lexicon.json`）——パスは全て利用者が決めます。ハードコードはありません:

```json
{
  "roots": ["~/.claude", "~/.codex", "~/.gemini", "~/.config/github-copilot"],
  "lexicons": ["lexicon/lexicon.en.md", "lexicon/lexicon.ja.md"],
  "transcripts": "~/.claude/projects",
  "scan": [
    { "rules": ["M1"], "include": ["rules/**/*.md", "skills/**/*.md"], "exclude": ["ledgers/**"] },
    { "rules": ["M5"], "include": ["**/HANDOFF.md"], "exclude": ["ledgers/**"] }
  ]
}
```

2つのscanブロックで**スコープが違う**ことに注目してください。これは意図的で、ここが最重要の調整箇所です。
M1は指示文書に効かせます（誤読が作業の宛先を狂わせる場所だから）。M5は**自分の規約が既に絶対日付を要求して
いる場所**にだけ効かせます。全域に向けると、相対日付で何も問題ない散文に鳴り続けます——後述の「効くのは語でなく
スコープ」を参照。

### エージェントのdocはどこに住むか

1つの設定で複数のエージェントの拠点を同時に指せます——`roots`はリストを受け取ります。**存在しない拠点は
黙ってスキップされます**。全部インストールしている人はいないからです。aliveの行が
`roots=<存在>/<宣言>` を出すので、実際に何を走査したかが見えます:

```
[misread-lint] alive: rules=4 roots=2/4 targets=138
```

（宣言4拠点のうち2つが実在する機での実測値。数字は環境で変わります——`rules` は台帳の行数、
`targets` はglobが実際に一致したファイル数です。）

| 環境 | 拠点 | 指示docの置き場 |
|---|---|---|
| Claude Code | `~/.claude` | `CLAUDE.md`、`rules/`、`skills/`、`workflows/` |
| OpenAI Codex | `~/.codex` | `AGENTS.md`、`skills/` |
| Gemini CLI | `~/.gemini` | `GEMINI.md` |
| GitHub Copilot | リポジトリ内 | `.github/copilot-instructions.md` |
| Cursor | リポジトリ内 | `.cursor/rules/**`、`.cursorrules` |
| 共通 | リポジトリ内 | `AGENTS.md`、`HANDOFF.md` |

プロジェクト単位のdocはホームディレクトリでなく、作業しているリポジトリの中に住みます——そちらのパスも
`roots` へ足してください。例: `"roots": ["~/.claude", "."]`。

**正直に書く限界**: `mine_misreads.py` が検証済みなのはClaude CodeのJSONLトランスクリプト形式だけです——
`type: "user"`/`"assistant"` のレコードと、Anthropic形式の `message.content` ブロック。他ベンダーは会話
履歴を別の形で保存しており、この採掘器はそのどれに対しても検証されていません。誰かが確かめるまでは
Claude Code専用として扱ってください。このリポジトリはそれ以上の対応を謳いません。

## 実際に発火させる

ここまでで手に入るのは「思い出して走らせる道具」です。それは機構ではなく**道具＋意志**で、
壊れるのは意志の方です。あと2手で輪が閉じます。

**1. skillを置く＝誤読の指摘が登録へ向かうようにする。** 自分の言語のskillをエージェントの
skillsディレクトリへコピーします。これで「読み間違えている」と言われた瞬間に、謝るのではなく
台帳へ誘導されます:

```bash
mkdir -p ~/.claude/skills/misread-lexicon
cp skill/ja/SKILL.md ~/.claude/skills/misread-lexicon/   # 英語なら skill/en/SKILL.md
```

コピーしたファイル内のパスは、このリポジトリと設定を置いた場所に合わせて書き換えてください。

**2. スイープをセッション開始へ配線する＝誰も覚えていなくてよくする。** Claude Code なら
`~/.claude/settings.json` の `hooks.SessionStart` へ1本追加します（既存のフック配列に**マージ**。
置換しないこと）:

```json
{
  "type": "command",
  "command": "python /path/to/agent-misread-lexicon/tools/check_misread_words.py --config ~/.claude/misread-lexicon.json || true",
  "timeout": 30
}
```

`|| true` は必須です。linterは検出時にexit 1を返すので、素通しだとフック失敗として扱われます。
スイープは約60ファイルで0.4秒、先頭行はASCII固定なので端末の符号化に関係なく読めます。

**そして発火を確かめる——仮定で済ませない。** フックを入れたことと、その出力が届いたことは
別の出来事で、証拠になるのは後者だけです:

```bash
# 設定したM1スコープの中へ、わざと違反を仕込む
echo 'probe: UE bare token' > ~/.claude/templates/probe.md
# 新しいセッションを開始し、冒頭に検出行が出ることを確認する
rm ~/.claude/templates/probe.md
```

ここを飛ばすと、このリポジトリが扱っている当の失敗になります——**設置済みで、緑で、
一度も届いていない機構**。

**3. 任意——読む時でなく書く時に捕まえる。** セッション開始のスイープが鳴るのは「次に誰かが
セッションを開いた時」で、その頃には書いた側はもう別の作業に移っています。`--hook` は
**今書き終えた1ファイルだけ**をその場で検査します。Claude Code なら:

```json
{
  "type": "command",
  "command": "python /path/to/agent-misread-lexicon/tools/check_misread_words.py --config ~/.claude/misread-lexicon.json --hook --emit claude",
  "timeout": 10
}
```

`hooks.PostToolUse` の matcher `Edit|Write|MultiEdit` へ登録します。`--hook` は書かれたファイルの
パスを stdin から読みます——一般的な形の JSON ツールイベントでも、**素のパス1行**でも受けます
（後者はエディタの保存フックや CI ステップが送る形です）:

```bash
echo path/to/HANDOFF.md | python tools/check_misread_words.py --config my.json --hook
```

挙動を、守ってくれる順に:

- **検査されるのは設定のscanブロックが覆うパスだけ**——それ以外は沈黙して素通り＝書き込みの大半は
  インタプリタ起動1回分（実測 約0.2秒）しか掛からない
- **報告するだけで、遮断しない。** 書き込みは既に済んでいます。書いた後のゲートはファイルを
  書き戻せませんし、書き込みを拒む検査器は最終的に**引用を書き換えて満たす**ことになります
- **しつこく鳴き続けず、黙る。** 同じファイルが*同じ検出数*のまま再報告されたら、繰り返し警告を
  1回出してそのセッションでは沈黙します。数が変われば——増でも減でも——新しい報告として扱います。
  抑制状態は temp のファイルに置かれ（`--state PATH` で移動可）、消えても「1回余計に報告される」
  だけ＝安全な側に倒れます
- 常に exit 0＝検出がフック失敗と誤認されない

`--emit` は出力の契約に名前を付けたものです: 既定の `text` は所見を stderr へ出し、どのエディタ・
CI ホストにも合います。`claude` は Claude Code の PostToolUse がエージェントへ戻す
`{"decision": "block", "reason": ...}` JSON を出します。値の名前をベンダー名にしたのは意図的です——
あの JSON の形は Claude Code のものであり、それを無印の既定に据えるのは、まさにこのリポジトリが
警告している類の「静かなベンダー前提」だからです。

スコープは同じ設定から解決されます。1つだけ知っておく規則: **`**/` で始まるパターンは場所非依存、
それ以外は root 固定**。つまり掲載の設定のままで `**/HANDOFF.md` は*どこに書かれた* HANDOFF にも
効き（rootとして宣言していないプロジェクト配下＝スイープには構造的に見えない場所を含む）、
`rules/**/*.md` は宣言済みrootの中の rules ディレクトリのままです。

同じスコープ規則は CLI からも `--paths FILE --respect-scope` で使えます。素の `--paths` は従来どおり
（指定した全ファイルへ全ルールを当てる）で変えていません。

## 使う

```bash
python tools/check_misread_words.py                    # 設定したスコープを走査
python tools/check_misread_words.py --paths FILE ...   # 特定ファイルだけ
python tools/mine_misreads.py --out candidates.jsonl   # 過去ログから誤読を掘り起こす
python tools/trace_misreads.py --sweep                 # 誰も報告しなかった分を掘り起こす
python tools/probe_misreads.py --runner "claude -p {prompt}"   # 書き換えは効くのか
```

検出ありでexit 1、無しで0。**ファイルを書き換えることはありません**——位置と「伝わる形」を出すだけで、直すかは
利用者が決めます。

## 台帳は育つ、コードは育たない

linterは実行時に台帳のテーブルからルールを読みます。語の追加はテーブル1行です:

```
| M1 | UE | UE(Unreal Engine)（ファイル内初出時。以後は裸でよい） | 例 |
```

コード変更も再配布も要りません。上の配線を済ませていれば**走らせ直す必要もありません**。
**想定している運用は「実際に誤読が起きたその場で1行足す」**——この台帳は他人が推測した辞書ではなく、
**自分の事故の記録**です。だからほぼ空で出荷されます。

テーブルはヘッダ文字列ではなく**マーカーコメント**で位置特定するので、台帳は何語で書いても動きます。列は
位置で決まります（型・誤読される形・伝わる形・根拠）。

## 既に起きた誤読を回収する

前向きに育てるだけだと、ゼロから始めて痛い目に遭うのを待つことになります。`mine_misreads.py` は既存の
エージェント・トランスクリプトを読み、**既に起きた訂正**——人間が「そうじゃなくて」と言った瞬間——を、その直前に
エージェントが何を読んでいたかと一緒に出します。

候補は2段で報告されます: 読み違いを明示的に名指した発話と、一般的な訂正。パターンは英日両対応です。これは
**ゲートでなくレポート**なので常にexit 0を返します——どれが本物かは人が決める必要があるからです。

**歩留まりは低く、それでいい**。参照コーパスでは発話1220件から生の一致51件、そのうち大半は機械生成の会話
要約で、除外が必要でした。残ったのは僅かです——が、登録する価値があったのはその僅かの方でした。

## 誰も報告しなかった誤読

ここまでは全部、**誰かが気づいた**ことが前提です。`mine_misreads.py` が拾うのは人間が「そうじゃなくて」と
言った瞬間なので、二重に盲目です——人間が気づく必要があり、しかも口に出す必要がある。その数が実際に
測っているものを書き下すとこうなります:

```
報告された誤読  =  実際の誤読  ×  それが報告される確率
```

1本の式に未知数が2つ。**だからこの数が下がっても何の証拠にもなりません**——誤読が減ったのと白状しなくなったのは、
この側からは同じ形に見えます。このrepoを入れて数字が下がっても、まだ何も分かっていない。自己申告に基づく誤読率は
全部この状態で、それはこのrepo自身も例外ではありません。

`trace_misreads.py` は式のもう一方を読みます。誤読は、**誰かが捕まえたかどうかに関係なく**、
トランスクリプトへ機械的な痕跡を残す。しかもその痕跡には分母が付きます。

```bash
python tools/trace_misreads.py --sweep
```

### シグナル1 — 空振り即断（assert-on-empty）

検索が0件で返り、次の返答が「それは存在しない」と結論する。外れたのは読み手の語彙なのに、出てきた主張は
あなたのコードベースについてのものになっている。これは M3——このREADMEが「検出不能」と書いた類型です。
そして確かに**文書の中では**検出不能ですが、振る舞いの中では明白です:

```
[trace-misreads] alive: transcripts=107 searches=635 zero_hit=88
[trace-misreads] assert-on-empty: 8/88 (9.1%) never questioned by a human: 8
```

0件で返った検索が88回。うち8回がそのまま「存在しない」に化けており、**その8件はどれ一つ、後から人間に
疑問視されていません**。8件を手で検分した内訳は、真6・誤2（機能でなく「隙間」の不在を言っているもの＝
*「その隙間が存在しません」*と、表の中に引用されたシェル出力）。

ここで効くのは、**この数はごまかせない**ということです。この検出は、エージェントが不確かさを申告*しなかった*
ことによって生まれる。黙るほどこの数は下がるどころか上がる。ここでは沈黙が分子です。

### シグナル2 — 語彙ギャップと、それが一般化する軸

検索が0件で返り、後から**同じ概念を別の綴りで**引いた検索が当たる。この対が、2つの綴りが何の軸で
違っていたかを名指します:

```
[trace-misreads] vocabulary-gap: 25 pair(s) axes={anchor:9, case:1, dash:2, other:13}
  [case]   'rtk'                  で探し  -> 'rtk|RTK'                          で見つけた
  [anchor] 'tests/test_*.py'      で探し  -> '**/test_*.py'                     で見つけた
  [dash]   '能力差|complementarity' で探し  -> 'Claude–Codex能力差|Claude-Codex能力差' で見つけた
```

こちらが**先回り側**で、語ではなく軸を記録する理由がここにあります。焼かれた「語」は1件の事故ですが、
焼かれた**軸**は予測になる——同じ軸に晒されている他の語は全部、**まだ起きていない誤読**です。

`--sweep` がその予測を出します。実際に検索を失敗させた軸だけを掃き、しかも**自分のcorpus内で両方の綴りが
観測できる衝突**しか報告しません（辞書からの推測を持ち込まないため）:

```
[trace-misreads] sweep: axes=['dash'] docs=577 exposed=2
  [dash] A-C / A−C  (adversarial_prompts.md, attempt_agent.md)
```

`A−C` は U+2212 で書かれています。`A-C` と打った検索は永久に届きません。**まだ何も起きていない**——
それがこのチャネルの存在意義です。

### 実測に耐えた軸は1つ、落とした軸が3つ

| 軸 | 577文書での検出数 | 判定 |
|---|---|---|
| `dash`（打てないダッシュ） | 2 | 採用 |
| `case` | 52 | 不採用: ほぼ全部が見出しのタイトルケース（`Multi-Agent` / `Multi-agent`） |
| ハイフン vs `_` | 58 | 不採用: 多くはCLIフラグと同名変数が並んでいるだけ |
| `anchor` / `space` | — | ギャップとしては報告するが、推測にならない文書側の形が無い |

軸は、**スイープ対象でなくてもギャップ報告には残ります**（実際に検索を失敗させた＝証拠だから）。予測として
出す以上は読む価値が要る、という線引きです。この不採用は自己テストで固定してあるので、戻すなら
なし崩しではなく明示的な編集になります。

### それでも見えないもの

**検索を一度も走らせなかった誤読は、ここには痕跡を残しません。** 読み手があなたの語を取り違えたまま
そのまま作業へ入った場合、このツールももう一方と同じく盲目です。主張は意図的に狭くしてあります——
**検索を通った誤読を、分母付きで、誰の自白にも頼らずに数える**。あなたのセッションの誤読率ではありません。

通常はexit 0、**何も検査できなかったときだけ exit 2** です——0件しか見ていない検査器が「検出なし」と
報告するのは、このrepoが反対しているまさにその失敗だからです。

## 語を書き換えると、本当に効くのか

上の2チャネルは誤読を**数える**だけで、台帳が存在する理由そのもの——**行を「伝わる形」に書き換えたら
何か変わるのか**——には答えていません。

`probe_misreads.py` はそれを実験として走らせます。プローブとは「1つの語を含む1つの課題」で、その語を
2通りに書いたもの。`raw:` が誤読される綴り、`hardened:` が台帳3列目の綴りです。fixtureも課題も他は
完全に同一なので、モデルの機嫌もその日の調子も両アームに等しく乗って打ち消し合います:

```
誤読率(rawアーム) − 誤読率(hardenedアーム) = その1行が買ってくれたもの
```

この数字に自己申告は一切入りません。採点は**成果物**だけを見ます（どのファイル名を答えたか、どのIDを
答えたか）。だから「間違いを認めなくなったエージェント」はこの数字を動かせない。白状率も測りますが、
**別の数字**として、しかも成果物が既に誤りだと証明した試行に限って測る。数字が2つになると、
2つの失敗モードが分離します:

| | 白状率が横ばい | 白状率が下がる |
|---|---|---|
| **誤読率が下がる** | 本当に読めるようになった | 読めるようになり、かつ喋らなくなった |
| **誤読率が横ばい** | 何も変わっていない | **黙っただけ** |

エージェントは同梱しません。あなたのを渡してください:

```bash
python tools/probe_misreads.py --list                          # 何が走るか
python tools/probe_misreads.py --runner "claude -p {prompt}"   # 走らせる
```

`{prompt}` が課題、`{dir}` が作業ディレクトリ。シェルを介さずに起動するので、空白入りのWindowsパスを
引用符で囲んでも壊れません。

### プローブは1ファイル1プローブのMarkdown

```markdown
---
id: example-m3-vocabulary-gap
type: M3
raw: perimeter throttle
hardened: perimeter throttle (rate limit)
runs: 2
---
## task
gateway.md を読んで、このサービスが1クライアントあたりのリクエスト数を制限しているか答えてください。
`yes: <機能名>` または `no` で答えること。

## fixture: gateway.md
The {{term}} rejects a client that goes over its budget for the window.

## correct
perimeter throttle

## misread
/^\s*no\b/
```

`{{term}}` は1つ、綴りは2つ、それ以外は2アームで完全に同一。`## correct` は必須です——正解と
クラッシュを区別できないプローブは、採点せず**読み込み時に拒否**します。パターンは部分一致か、
1行 `/正規表現/`。

このプローブが測っているのは **M3（語彙ギャップ）**——このREADMEが「検出不能」と書いた類型です。
linterは「誰も書かなかった語の不在」を見つけられませんが、プローブは測れる: 文書が*著者の語*で
書いている機能について、*読み手の語*で質問し、答えがどちらへ転ぶかを見ればいい。

### 何も書かなくても走るプローブ

台帳はほぼ空で出荷されるので、それだと走るものが無いハーネスになってしまいます。だから台帳の行からも
プローブを生成します——**2列目と3列目が、そのまま実験の2アーム**だからです:

```
[probe-misreads] alive: probes=4 arms=2 trials=8 failed=0
  example-m3-vocabulary-gap  M3  raw='perimeter throttle'  hardened='perimeter throttle (rate limit)'
  auto-m1-UE                 M1  raw='UE'                  hardened='UE (Unreal Engine)'
  auto-m5-yesterday          M5  raw='yesterday'           hardened='2026-08-02'
```

同じidの手書きプローブがあれば**常にそちらが勝ちます**（手書き＝実際の事故、生成＝雛形だから）。
公平な問いを作れない行は、黙って捨てずに数えて報告します（`lexicon rows with no auto probe: 9`）。

### 初回の実走は「効果を検出できなかった」と言った

実エージェント相手に8試行:

```
[probe-misreads]      raw arm: misread 0/4 (0%, 95% CI 0-49%) ambiguous=0
[probe-misreads] hardened arm: misread 0/4 (0%, 95% CI 0-49%) ambiguous=0
[probe-misreads] the row bought you: +0 points of misread rate
```

ゼロより先に**信頼区間**を読んでください。**1アーム4試行では、40ポイントの改善と無効果を区別できません。**
正しい要約は「台帳は効かない」ではなく「**この実験には検出力が無い**」で、処方は主張を大きくすることでは
なく、試行数を増やし、実際に自分に起きた誤読からプローブを書くことです。

実走でしか出てこなかった問題が2つ。どちらも修正済みか明記済みです:

- **答えではなく推論を採点していた**。エージェントは `D-A` と正しく答えた上で、*「今日基準で読むと
  誤って D-B になる」*と説明した——その一文に誤答パターンが当たっていました。現在は**まず答えの行**を
  採点し、答えの行で決まらないときだけ全文へフォールバックします。
- **被験エージェントがあなたの指示文書を読んでいる**。ある試行は裸のトークンを解決した上で、出所まで
  書いていました——テスト実施者自身の台帳です（ホームディレクトリから読み込まれている）。rawアームに
  答えが手渡されていたことになる。

  Claude Code には専用のスイッチがあります——`--bare` が hooks や auto-memory と一緒に
  **CLAUDE.md の自動探索を切ります**。ただし信用する前に測るべき条件が付きます:

  | 経路 | CLAUDE.mdを止める | 認証が残る |
  |---|---|---|
  | `--bare` / `CLAUDE_CODE_SIMPLE=1` 単独 | はい | **`ANTHROPIC_API_KEY` がある場合のみ**——OAuthでは `Not logged in`（実測） |
  | `--setting-sources project` | **いいえ**——実測でuserのCLAUDE.mdがロードされたまま | はい |
  | `--isolate-home`（本ハーネス） | はい | 同じAPIキー条件 |

  つまりAPIキーのランナーで走らせれば汚染は消え、ブラウザログインのまま走らせれば消えず、rawアームは
  答えを手渡され続けます。これは**ハーネスでなくエージェント側の性質**で、数字の読み方に含めるべき事実です。

### プローブを噛ませる3つの試みと、その実測

プローブは**一度でも捕まえられて初めて計器**です。3設計・22試行、rawアームは一度も落ちませんでした:

| 設計 | エージェントが実際にやったこと | rawアーム |
|---|---|---|
| 小さなfixture 1枚 | 全部読んだ | 0/5 |
| `filler: 300`（読み切れない規模のcorpus） | 同義語を束ねてgrep→外して広域再走査 | 0/3 |
| 4項目チェックリストの3番目に質問を埋める | 同上 | 0/3 |

2番目の試行でエージェント自身が残した証拠行: `Grep -i "throttle|rate limit|429|quota|token bucket|…"
→ 1 hit`、続いて `limit|cap|budget|API key|…` → 27 hits。**始める前から同義語を列挙する読み手は、
語彙ギャップでは捕まりません**。（`filler: N` は本物のノートの周りにN枚の紛らわしいノートを置く機構で、
表の2行目がその実測です。足りませんでした。）

理由は修正可能な不備ではなく**構造**に見えます。採掘した実インシデントはすべて、長いセッションの深部で、
検索が別の目的の下の「50手のうちの1手」だった時に起きている。プローブは短く新鮮なセッションで、
**その1問だけが目的**です——1問に全注意を向けた読み手は慎重になる。

だから宿題ではなく**適用範囲**として書きます: **`probe_misreads.py` が測るのは「短く新鮮なセッションで
書き換えが振る舞いを変えるか」**。このrepoが相手にしている誤読は、**長く重いセッション**で起きます。
これは手法の境界であり、実物を見ているのは `trace_misreads.py` の方です。

### 実測したギャップをプローブへ変える

`trace_misreads.py --emit-probes DIR` は、採掘済みのギャップからプローブを組みます（対が実測なので、
2アームが**捏造でなく実在の綴り**になる）。候補を並べるだけで、`--gap ID` で名指しするまで1本も書きません:

```
[trace-misreads] convertible gaps: 12 of 25. Pick the pair that is two names for one thing.
  gap-codex-claude-complementa   doc says 'codex_claude_complementarity' / reader looked for '能力差'
  gap-character-generator        doc says 'character-generator' / reader looked for 'character generator'
```

全部書き出す版も作って測りました: **12本生成して、本物の語彙対は1本**。「2つの検索が近くで走った」ことは
機械に見えても、「2つの語が同じものを指すか」は文字列比較に答えられる問いではないので、そこは人が決めます。

通常はexit 0、**1件も採点できなかったときだけ exit 2**（プローブが無い／ランナーが何も出力しない）。
試行0件の上に載った率は結果ではありません。

## 効くのは語でなくスコープ

このツールの初回実走は検出3件と**誤検出1件**を出しました。そしてこのREADMEで一番役に立つのは誤検出の方です。

M5が個人的なノートの中の `明日` に発火しました。そこでの用法は概念的で——*「熱だけで再建
された明日」*——しかも一部は本人の発言の逐語引用でした。腐っているものは何もありません。**ルールは正しく、
スコープが間違っていた**。

処方は文を書き換えることではありません。**引用をlinterに直させてはいけない。** 処方はM5の既定スコープを
引き継ぎ文書に絞ることで、そして**その行そのものを負対照テストへ焼く**ことでした（スコープが黙って広がらない
ように）。

このリポジトリが求める規律はここです。検出器が誤爆した時の最初の問いは「検査器を満たすようにどう書き直すか」
ではなく、**「このファイルはそもそもスコープ内だったのか」**です。

### ⚠ このREADMEは意図的にcleanにならない

`--paths` は設定したスコープを無視して全ルールを当てます。だからこのリポジトリ自身のdocに向けると検出が出ます——
相対参照**について**書いた文書には、必然的に `昨日` や `明日` が出てくるからです。

その大半は**使用でなく言及**で、コードスパンで囲んであります（linterが免除する形）。残るのは2ファイル合計で4件、
そして**その4件は全部が引用**です——上の節の引用文が各1件、そしてプローブの節で引用したエージェント自身の説明
（`今日基準で読むと誤って D-B になる`）が各1件。どれも検出されたまま、**書き換えずに残してあります**。
書き換えるとは、ツールが自分を満たすために人の言葉を直すということだからです。しかも後の2件は、この節が
警告しているまさにその経路で増えました——**ツールについて書いたら、その文章をツールが検出した**。

どちらのファイルも既定の走査スコープには入っていないので、通常のスイープでは一度も見られません。教訓がそのまま
縮図になっています——**問題だったのはルールではなく、スコープの方**。

## これは何ではないか

- **スペルチェッカでも文体linterでもない**。散文の良し悪しに意見を持ちません。既に誤読された語の形だけを、
  しかも**登録された分だけ**知っています。
- **ガードではない**。何も遮断せず、何も書き換えません。報告して終わります。
- **符号化の修理屋ではない**。M2は網羅のために載せていますが、意図的に検出器を持ちません。
- **ファイルを読むことの代わりにはならない**。実測で最多だったM3は、まさにどんなツールでも捕まえられない型です。
  「その機能は無い」と言う前に、在るならそこに書かれているはずのファイルを開いてください。空振りした検索が
  証明するのは**自分の語彙が一致しなかったこと**だけで、対象の不在ではありません。
